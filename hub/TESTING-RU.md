# Параллельная проверка Connect Hub

Это ранняя версия 0.1 alpha для проверки. Существующие панели, базы, ключи,
сертификаты и службы не используются. Реальные VPS при разработке не менялись.

## В контейнере

Нужны Git, Docker и Docker Compose с доступом к Docker. Выполняйте из отдельной
папки с исходниками Connect Hub. До слияния PR используйте ветку
`feat/connect-hub-v0.1` из репозитория `sanderstripa/connect-hub`.

```bash
docker compose build --build-arg CONNECT_HUB_REVISION="$(git rev-parse HEAD)"
docker compose up -d
hub_address=$(docker compose port connect-hub 2053)
docker compose exec -T connect-hub cat /etc/connect-hub/initial-access.txt | sed "s|http://127.0.0.1:2053|http://$hub_address|"
```

Последняя команда выводит адрес, имя пользователя и пароль. Порт выбирается
автоматически. Адрес доступен только с машины, где работает Docker; для браузера
на другом компьютере используйте SSH-перенаправление этого порта.

Проект Compose называется `connect-hub-test`, данные хранятся в его собственных
томах. Сеть хоста, папки других панелей и привилегированный режим не используются.
Для остановки выполните `docker compose down` в этой же папке. Данные сохранятся.
Чтобы проверить внешний клиентский трафик, отдельно добавьте в Compose только
те свободные TCP/UDP-порты, которые создали в Connect Hub.

## Отдельная системная служба

Скачайте артефакт `connect-hub-linux-amd64` из успешного прогона GitHub Actions
для нужной ревизии PR. Распакуйте ZIP, затем выполните в полученной папке:

```bash
sha256sum -c SHA256SUMS
tar -xzf connect-hub-linux-amd64.tar.gz connect-hub/hub/install.sh
sudo bash connect-hub/hub/install.sh --package connect-hub-linux-amd64.tar.gz --sha256 "$(awk '$2=="connect-hub-linux-amd64.tar.gz" {print $1}' SHA256SUMS)"
```

Пакет предназначен для Linux amd64. Установщику нужны Python 3.12+, OpenSSL,
curl, sha256sum и systemd. Проверен запуск бинарника на Debian 12; полная
установка и сетевые проверки выполнены на отдельном Ubuntu 24.04 runner в CI.
ARM64 предусмотрен сборщиком, но не прошёл такую же проверку.

Создаются только `/opt/connect-hub`, `/etc/connect-hub`, `/var/log/connect-hub`,
пользователь и служба `connect-hub`. Если одноимённая служба, пользователь или
папки уже существуют, чистая установка откажется от их использования.

Случайные адрес и пароль доступны через:

```bash
sudo cat /etc/connect-hub/initial-access.txt
```

Панель слушает свободный порт на `127.0.0.1`. Внутренние порты Xray тоже
выбираются отдельно; подписки изначально выключены. Новым подключениям задавайте
свободные порты. Занятый другой программой порт не освобождается принудительно.
Установка не меняет firewall, DNS, маршруты или сертификаты.

Для остановки: `sudo systemctl stop connect-hub`. Обновление выполняется той же
командой установки с дополнительным `--update`: перед ним сохраняется резервная
копия, при неудаче восстанавливается предыдущая версия. Автоматического удаления
резервных копий нет. Обновление через старые скрипты x-ui отключено.

## Что уже проверяется

Вход, CSRF, резервная копия базы, создание подключения и реальный HTTP через
Xray; запуск при занятых стандартных портах; отдельная непривилегированная
служба; обновление с сохранением доступа и откат сломанного обновления;
контейнерная изоляция и перезапуск. Дополнительно проверяется реальный TCP
Sudoku с совместимым core-v0.7.0 и чтение статуса настоящего Connect Core.

Sudoku по умолчанию выключен и пока управляет одним сервером и одной новой
клиентской идентичностью. Connect Core alpha только показывает статус: запуск
VPN и управление устройствами не реализованы. Mist недоступен до подтверждения
контракта интеграции и лицензии. Настройка: [INTEGRATIONS.md](INTEGRATIONS.md).
